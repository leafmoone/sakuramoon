## Strict JLT remediation

The original M033 implementation and its test/timing/review evidence remain historical
and unchanged. The remediation replaces the clamp-region target with the strict shared
conversion:

```text
d = max(1-t, 0.05)
v_target = (clean-state)/d
v_pred = (x_pred-state)/d
loss = MSE(v_pred,v_target) = MSE(x_pred,clean)/d^2
```

The runtime objective contract now records the exact loss, target conversion, and
inverse-square clamped weighting. The maximum endpoint weight is 400. High-noise
observation sums/counts use `t<0.5`; low-noise sums/counts use `t>=0.5`; neither changes
the full-batch loss reduction and empty buckets are not represented as a zero mean.

Adding the objective identity fields changes the resolved config hash. Existing raw
checkpoints therefore fail the current config identity check before model mutation and
cannot silently resume under the remediated loss. Existing model-only weights remain
loadable for inference but must be treated as `pre_fix`; M034 owns recording that
provenance in generation metadata.

The remediation does not modify checkpoint format, training-step integration, DDP
global-mean behavior, or sampling profiles. M034 owns the three fixed sampler profiles.
