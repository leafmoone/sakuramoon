# T021: Frozen Qwen text encoder

Status: code and real 1GPU forward/kernel validation complete; package review pending.

## Scope

- Load only `model/qwen_3.5_2B` with local-files-only and no fallback.
- Instantiate `Qwen3_5ForCausalLM` from the text config, retain only its text model, and never build or call a visual path.
- Freeze eval/inference execution, force `use_cache=false`, and select after blocks `2/4/8/12/16/20/24` from one forward.

## Evidence

- Real CPU weight load: 24 layers, hidden size 2048, zero missing/unexpected keys, no visual module.
- `tests/unit/encoders/test_qwen.py`: 3 passed.
- Package Ruff and strict Pyright passed.
- RTX 5090 BF16: `[1,L,7,2048]` finite outputs at all full dense lengths
  `98/162/226/290/354/418/482/546`, with 3,700.4 MiB peak allocated memory.
- After fast-kernel compilation, batch-1 forward latency across those lengths was
  34.7-38.2 ms. The first compile-bearing forward took 39.7 seconds and is not
  reported as steady-state training latency.

Caption serialization and end-to-end enforcement of one Qwen call per sample remain
owned by D014 and the training integration; this wrapper does not claim those tasks.
