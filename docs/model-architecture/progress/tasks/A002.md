# A002: 本地加载边界简化

状态：原执行硬边界方案已撤销；最小规则并入实际加载任务，不再阻塞单卡主线

## 变更决定

原 A002 为阻止本地模型下载和 `reference/` 执行，扩展成大型 AST scanner、provenance/taint/fact algebra、冻结源码摘要、capability 防伪和十一轮修复。该实现规模与个人项目的真实风险不相称，现整体撤销，不再保留为工程要求或验收门槛。

撤销范围包括：

- `tools/asset_execution_boundary.py` 及专属 contract scanner。
- AST provenance/taint/fact algebra、源码结构 SHA pin、跨模块 callable 推导和高阶调用审计。
- verified selection/root capability、identity registry、反射/伪造/TOCTOU 防护。
- reference Git hostile-config 审计和为 scanner 建立的专用例外体系。
- A002 十一轮实现、性能和独立审查证据。

## 保留的最小规则

- Qwen TE 固定从 `model/qwen_3.5_2B/` 本地加载。
- Mage-VAE 固定从 `model/vae/` 本地加载。
- 实际加载前检查必需路径/文件；缺失或加载失败时直接报错。
- 禁止自动下载、缺失补下载、联网替换和 fallback。
- `reference/` 只供人工理解和对照；项目代码不 import、执行或调用其中代码。

这些规则由 `T020`、`T021` 和训练 preflight 的普通 unit/integration 测试覆盖，不再用全仓 AST scanner 证明。D010 的 ModelScope WebDataset 网络流式传输、revision 固定和 shard 完整性校验是独立的数据链路要求，继续保留。

## 结果

A002 不再是 `D010` 或后续单卡开发的前置任务。后续工作直接推进数据、encoder、模型和训练链路，不再为假设的恶意本地环境或外部兼容场景增加实现。
