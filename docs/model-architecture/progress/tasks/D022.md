## State contract

- Persist schema v3 with the immutable manifest SHA-256, explicit positive
  `worker_count`, sorted unique `active_shards`, completed shards, and cumulative
  replay counters. The active set may never exceed `worker_count`.
- Reject worker-count drift on load and hard-fail schema v1/v2. No migration or
  topology fallback is provided.
- Publish activation before cache fetch and pass the complete active set as protected
  paths on every fetch. A cache quota conflict therefore fails instead of evicting a
  shard still owned by any worker.
- Complete each shard independently while retaining every other active shard.
- On restart, add every active shard and its manifest sample count exactly once to the
  cumulative replay counters. Block activation of any new shard until every recovered
  active shard has been successfully prepared again.
- Preserve the existing singleton `lease()` behavior and `active` view for the D015
  one-worker path.

## Scope boundary

D022 changes only the parent coordinator state model. It does not modify the D015
pipeline/collate scheduling guard, launch persistent workers, let workers write state,
serialize queues, or claim durable two-worker throughput. Those changes belong to
D023.
