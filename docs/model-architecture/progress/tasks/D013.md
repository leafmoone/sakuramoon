## Scope

- Apply Pillow EXIF transpose once and convert the decoded image to RGB.
- Generate the exact 17 transpose-closed 512-equivalent buckets from `A0=512^2`, `q=32`, minimum short edge 256, and maximum aspect ratio 4:1.
- Scale the same shape family exactly to 256, 768, and 1024 stage edges.
- Route using post-EXIF dimensions, filter all buckets that would upscale, select the nearest `log2(W/H)` aspect, cover resize, and deterministically choose a uniform crop offset.
- Reject the sample when crop retention is below 0.80.
- Stream the full manifest dimension inventory into assigned/no-upscale/retention and
  per-bucket counts, requiring exact equality with the D010 aggregate sample count.
- Compare exactly 100,000 declared dimensions with post-EXIF decoded dimensions;
  accept at most 0.1% mismatch and hard-fail above it with a diagnostic report.
- Publish the combined result as canonical JSON through a sibling temporary file,
  file fsync, and atomic replacement.

No alternate resize policy, fallback bucket, padding, image registry, plugin system, or compatibility layer is included.

## Implementation

The generated base shapes are eight portrait/landscape pairs plus 512x512. Bucket selection returns explicit `no_upscale` or `retention` rejection reasons for later scan accounting. Crop randomness is controlled by one caller-provided integer seed; stage/pass/sample seed derivation remains a D015 pipeline responsibility.

The Data package audit found that direct runtime callers could pass a non-finite or
otherwise invalid crop-retention threshold. Assignment now hard-fails unless the value
is an exact finite float in `[0, 1]`; NaN, infinities, integers, booleans, and
out-of-range values have explicit negative contracts.

The scan code is streaming: it retains only two rejection counters and one counter per
configured bucket. The decode scan retains only match/mismatch counts. Synthetic tests
exercise the locked 100/100,000 inclusive boundary and 101/100,000 failure without
claiming a real decode scan.

D018 adds deterministic P01/P50/P99 accepted-crop retention quantiles through a fixed
10,001-bin histogram at `1e-4` resolution. Memory is constant in manifest size;
nearest-rank results have less than `1e-4` quantization error, and an all-rejected scan
reports `null` rather than fabricating a percentile.

Main-agent review found three additional contract gaps. Direct construction of scan
evidence accepted non-integer counters, negative bucket counts, duplicate or
non-canonical bucket order; these dataclasses now enforce exact integer/boolean/float
types, non-negative accounting, unique canonical ordering, and internal totals. Crop
execution now requires an exact integer seed and rejects booleans. D017 subsequently
replaced the obsolete no-clobber hard-link publisher: regenerable reports now use a
unique sibling temporary file, file fsync, and `os.replace`; a failed replacement
preserves the previous report and removes the task-owned temporary file.
