# T054: System and training fault injection

Status: CPU and bounded single-GPU implementation, remediation, and independent AI/Infra
post-remediation rereviews are complete. The independent pre-remediation audit produced
three blocking findings, all closed by targeted fixes/tests and the appended reviews in
`reviews/T054/ai_review.md` and `reviews/T054/infra_review.md`. DDP reduction, NCCL rank
failure, all-rank synchronized stop, four-rank state-divergence guards, four-rank
checkpoint recovery, and formal multi-GPU fault canaries remain blocked.

A 2026-08-02 main-agent readiness revalidation found that importing the public
fault-injection package exceeded the fixed five-second subprocess readiness contract
because the package eagerly imported checkpoint and Torch dependencies. The public API
now resolves exports lazily. The three readiness variants, the 159-test CPU selector,
and the seven-test bounded single-GPU matrix pass after the fix. The historical
main-agent self-review remains preserved; independent post-remediation conclusions were
appended later and do not rewrite it.

## Implemented scope

- Strict canonical fault matrix with immutable pre/post snapshots for local batch,
  accumulation, attention backend, world size, optimizer identity, learning rate,
  checkpoint cadence, and resolved-config hash.
- Bounded subprocess driver using an inherited pipe readiness barrier, real `SIGKILL`,
  no worker stdout/stderr capture, a credential-free environment allowlist, timeout,
  and unconditional child reaping. The expected-exit driver uses the same allowlist.
- Real download-process kill with unpublished partial data and byte-zero rewrite on
  restart; truncated body, checksum mismatch, 401/403 no-retry regression, worker
  `os._exit()`, and cache/state/checkpoint/diagnostic `ENOSPC` hard failures.
- `WebDatasetPipeline.iter_leased_shards()` binds cache preparation and sample iteration
  to shard leases: interrupted or abandoned iteration keeps the shard active, while only
  normal exhaustion marks it complete. Restart skips completed shards and persists exact
  replayed-shard/sample counts.
- Exact raw recovery parent selector requires the requested checkpoint ID and update to
  name one verified `COMPLETE` raw checkpoint; it never selects latest, PMA, model-only,
  release, corrupt, incomplete, or a different update as fallback.
- Tiny engineering-only CUDA worker performs real BF16 forward/backward and TorchAO
  AdamW8bit mechanics before microbatch, optimizer, and checkpoint kill barriers.
  Fresh processes recover only the explicit complete parent, perform one next update,
  and verify every protected control field is unchanged.
- Real CUDA allocator OOM runs in a child process only after restoring an explicit
  `COMPLETE` parent, records `OutOfMemoryError` plus unchanged protected controls, exits
  without retry, and leaves both the GPU and parent recoverable by a fresh process. No
  batch, accumulation, backend, world-size, optimizer, LR, feature, or
  checkpoint-cadence fallback exists.
- The matrix binder loads one strict no-clobber evidence file for each CPU/1GPU scenario,
  verifies its test-report hash, hashes the exact parsed bytes, and publishes the
  canonical matrix. Missing, stale, mislabeled, unknown-field, or unbound scenario
  inputs fail before publication.

## Evidence boundary

The single-GPU worker is a 1-update mechanical harness, not the undecided production
S0 config, full Qwen/VAE/DiT chain, formal canary, capacity result, or training long run.
The host default NVML userspace library is mismatched with the loaded 580.105.08 driver;
the CUDA fault command explicitly preloads the installed matching 580.105.08 library.
This test-only environment correction is recorded and is not a runtime fallback.

`OPEN-078` and the CPU/1GPU portions of `OPEN-079` through `OPEN-081` have direct
implementation evidence, but mixed requirements that include DDP/NCCL/all-rank or
four-rank state equality remain blocked. In particular, single-GPU SR restoration does
not close SR RNG rank-divergence detection. No DDP/NCCL command, four-GPU run,
1,000-step canary, 100+500 production benchmark, or formal stage canary was executed.

The post-remediation readiness commands and exact bounded results are recorded in
`docs/model-architecture/reviews/T054/readiness_report.json`. The archive-reading trace
verifier and its unit wrapper were deliberately not run and are not acceptance evidence.
