## Scope

- Iterate only locally prepared D010/D012 shard paths through WebDataset; no dataset
  pre-download, model download, remote fallback, or `reference/` code path.
- Exclude validation IDs after one JSON parse and before caption/image processing.
- Decode one image, apply D013 EXIF/RGB/no-upscale bucket/crop, build one D014
  structured caption, and retain explicit audit and stage/pass/sample RNG identity.
- Group only identical image and Qwen dense buckets, pad with masked EOT, preserve
  structured main/Artist indices, and emit typed uint8 CPU batches.
- Require explicit persistent worker and ready-batch counts. The ready budget must
  divide exactly across workers; no silent queue-size adjustment is allowed.
- Keep only incomplete bucket fragments smaller than one batch. No text embedding,
  latent, activation, or cross-batch model cache exists.

The real dataset-to-`CaptionFields` mapping is an explicit callback because the
current documents do not define its raw field names. Production construction remains
blocked until that mapping and the eleven unresolved dropout probabilities are fixed.

The Data package audit found that D013 no-upscale and retention rejections escaped the
iterator. The pipeline now treats only typed `ImageRejected` outcomes as skipped
samples; decode, metadata, caption, tokenizer, and other contract failures still hard
fail. Real-tar tests prove both rejection reasons and continued iteration.

Independent follow-up review found that the ordinary loader bypassed the durable shard
lease, arbitrary URL-like values could reach WebDataset, rejection reasons were not
observable, collate padding was caller-selected instead of framing-bound, and boolean
settings relied on truthiness. The public durable batch iterator now keeps one D012
lease active until its loader drains normally, accepts only unique absolute local
regular files, requires an explicit rejection observer, carries the measured Qwen
padding ID on each sample, and validates exact booleans and construction fields.

D012 state records only one active shard while WebDataset splits workers by shard. The
durable correctness API therefore hard-fails unless `worker_count=1`; it never silently
changes the configured worker count. The existing 1/2/3-worker sweep remains mechanics
evidence only. A production multi-worker durable design and its cold-cache benchmark
remain blocked/pending rather than being inferred from the serial correctness path.

## Evidence

- Synthetic real-tar WebDataset, validation-before-decode, typed rejection observation,
  durable begin/complete, restart fault, framing-bound padding, bucket isolation and
  strict queue/config validation: 21 targeted tests passed in 12.74 seconds.
- The prior 1/2/3 persistent-worker sweep consumed three shard/sample IDs exactly once,
  but did not exercise D012 state and is not durable-resume evidence.
- Pre-final-worker-guard Data/text/fault integration suite: 205 passed in 18.00 seconds.
- Current full CPU repository suite: 553 passed, 5 skipped in 57.09 seconds.
- Real local tokenizer + RTX 5090 serial smoke: batch `[1,3,512,512]`, dense Qwen
  length 98, seven-state Qwen output `[1,98,7,2048]`, Mage latent
  `[1,128,32,32]`, all finite, 3,821.5 MiB peak allocated memory.
- Reproducible GPU selector passed in 16.69 seconds and asserts the same pipeline,
  Qwen, Mage, shape, finite and frozen contracts. It records no training or throughput
  claim.

The smoke's first-kernel Qwen/VAE times are not steady-state throughput. The required
cold-cache, worker/queue performance sweep, ready-wait, RSS, real rejection counts,
and full validation zero-leak scan remain milestone evidence.
