## Scope

- Derive trend/formal FID and IS jobs only from strict TOML successful-update cadence
  and stage-end settings.
- Bind each job to checkpoint kind/ID/resolved hash/checkpoint update,
  prompt/condition/seed/size manifest, successful-update trigger, CFG 2.9,
  Heun-50/99 NFE, sample count,
  extractor/version/preprocess, real-stat hash, IS splits, GPU index, and explicit
  training-pause policy. The content-addressed job ID must change when any of these
  fields changes.
- Load the configured prompt manifest as canonical JSON without following symlinks;
  treat its immutable case order as the fixed sample plan, use only `ordered_prefix`,
  and reject a manifest shorter than the scheduled sample count.
- Compute FID from CPU float64 feature statistics with PSD checks and compute IS from
  deterministic, exactly divisible splits. Immutable scalar artifacts reject
  impossible values before publication (`FID < 0` or `IS < 1`).
- Keep trend/formal/VAE/manual artifacts as distinct kinds, compare raw latest/PMA-10/
  accepted on the same generation/metric protocol, record evaluator GPU/pause cost,
  and forbid automatic release. Resource placement, local manifest path, and trigger
  update remain provenance but do not change checkpoint-comparison semantics.
- Reject checkpoints newer than the evaluation trigger, require raw latest to come from
  the exact trigger update, and permit an accepted comparison checkpoint to be older.
  An accepted release must name its own exact source-PMA path; preflight verifies that
  PMA's ten-source sidecar and strict-JLT lineage/topology independently of the current
  trigger PMA.
- Preserve manual tag control, aesthetic, NL following, composition, detail, and severe
  artifact dimensions instead of treating FID/IS as a release gate.
