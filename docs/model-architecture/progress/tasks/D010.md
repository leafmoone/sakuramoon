## Scope

- Fix the remote source to `leafmoone/webdataset_danbooru` and a 40-character commit revision.
- Describe every WebDataset shard with path, release, byte count, SHA-256, and sample count.
- Validate the remote tar inventory against the manifest.
- Download only a requested shard, stream it into `.partial`, hash while writing, then publish it with `os.replace`.
- Read `MODELSCOPE_API_TOKEN` only through the configured environment-variable name.

D010 does not pre-download the dataset. D011-D015 own metadata validation, cache coordination, image/caption processing, and the WebDataset training pipeline.

## Implementation

- `src/sakuramoon/data/manifest.py`: strict canonical manifest and config binding.
- `src/sakuramoon/data/modelscope.py`: small HTTPS listing/download client and verified shard publication.
- `src/sakuramoon/cli/manifest.py`: canonical manifest build plus local or remote verification.
- `src/sakuramoon/config/schema.py`: explicit source and transport settings.

The builder consumes two independent, explicit inputs. ModelScope enumeration supplies
only `path`, `bytes`, and SHA-256 for the configured commit revision. A canonical build
inventory, itself bound by an expected SHA-256 and the same source identity, supplies
only `path`, `release`, `samples`, license, and access terms. Both path inventories must
be non-empty, sorted/unique where canonical, duplicate-free, and exactly equal. Release
and sample count are never inferred from paths or remote metadata.

Build mode requires explicit `--inventory`, `--inventory-sha256`, and `--output`. The
output must equal the config-bound manifest path. Publication fsyncs the payload and
parent directory, is atomic, and refuses to replace an existing destination.

There is no capability registry, inode/dirfd protocol, TOCTOU layer, resume protocol, reference-code call, or local model hash check.
