# K001: FA4 varlen BF16 GQA production backend

Status: accepted-boundary benchmark remediation and 1GPU kernel validation complete;
independent AI and Infra rereviews pass for the implemented remediation. The FA4
production gate remains blocked on fixed upstream repository commit/license provenance,
which is not inferred from the locked wheel.

## Scope

- Consume flat T024 token streams with CUDA `cu_seqlens` boundaries directly; do not create a packed-to-dense production adapter.
- Keep native 20-query/5-key-value-head GQA and pass `pack_gqa=true` to FA4 without repeating K/V heads.
- Apply Q/K normalization and 2D RoPE before the varlen kernel, then the approved content gate and output projection.
- Require CUDA BF16 inputs and hard-fail when FA4 is unavailable or inputs violate the production contract. There is no silent fallback.
- Keep dense SDPA as an explicit reference implementation only.

## Evidence

- `tests/unit/model/test_fa4.py` and `tests/gpu/fa4/test_varlen_attention.py`: 16 passed on one RTX 5090.
- FA4 4.0.0b24 with NVIDIA CUTLASS DSL 4.6.0.dev0 executed real forward, backward, and parameter update.
- Fixed two-sample output, loss, Q/K/V gradients, and updates matched the dense SDPA reference within recorded BF16 tolerances; mutating sample two did not affect sample one.
- The complete attention module was loaded into an identical-state dense module and compared for output, loss, all seven named parameter gradients, and all seven BF16 parameter updates. Same-FA4-backend repeat p99 was zero for the recorded output and gradients.
- All 17 image buckets executed at empty, 39-token, and 512-token text boundaries.
- At lengths 1028 and 1540, batched CUDA Event timing reproduced 0.2180 ms FA4 versus 0.2895 ms mask-free dense SDPA (1.3281x). Per-call synchronized wall timing reproduced 0.2891 versus 0.3212 ms (1.1111x).
- The independent recheck reported 0.2217 versus 0.2932 ms (1.3225x) for batched Event timing and 0.2945 versus 0.3327 ms (1.1296x) for synchronized wall timing.
- Dense performance numbers always use separate samples with `attn_mask=None`. The observed 2.77 ms all-True-mask dense path is permitted only for numerical checking and is excluded from performance comparisons.
- `pack_gqa=true` remains locked: its independent 0.2243 ms result was slightly faster than 0.2262 ms with `false`, so there is no basis to change branches.
- M032 consumes this backend directly in its packed production model; there is no packed-to-dense production adapter.
- Current T024/K001 remediation rejects forged or mutated public offsets once at the
  packed entry, reuses a private accepted handle for all blocks, and derives sample
  routing from the same host identity. The current unit/GPU split is 6/16 (`22 passed`).
- Refreshed RTX 5090 benchmark at lengths `(1028,1540)` measured FA4/dense batched
  CUDA Event `0.216326/0.285460 ms` (`1.3196x`) and synchronized wall
  `0.288413/0.317405 ms` (`1.1005x`).
- A 16-block accepted-handle sequence measured hot-reuse p50 `3.561176 ms` and
  entry-inclusive p50 `3.625846 ms`; entry acceptance alone was `0.036929 ms` p50.
  Profiler evidence observed exactly 16 FA4 kernels, one D2H and one H2D per packed
  forward, no per-block boundary copy, and within-forward kernel-gap p95 `0.289 us`.
- Peak allocated/reserved memory was `31.349/36.0 MiB` for FA4 versus
  `43.888/50.0 MiB` for the mask-free per-sample dense reference.
- Output, loss, all seven parameter gradients, and all seven updates passed the
  identical-state dense comparison. Existing historical benchmark values remain in
  the evidence file and are not presented as current remediation measurements.
