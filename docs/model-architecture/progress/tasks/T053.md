## Implemented scope

- Enforce exactly 100 warmup plus 500 candidate measured updates, or at least
  1,000 final measured updates, from strict TOML.
- Build immutable workload identity from actual config/checkpoint/data/shape/software
  artifacts; stream exact typed sample-ID/shape observations across warmup and
  measured updates and hard-fail if either digest differs from the identity.
- Execute actual `SingleGpuStep` successful updates through an injectable adapter;
  retain per-update wall/CUDA spans for tail percentiles while using an explicitly
  synchronized boundary-to-boundary window clock for aggregate rates and shares,
  excluding post-window trace serialization;
  collect window peak CUDA memory, process-tree RSS high-water, bounded pinned/swap
  peaks, and bytes from actual checkpoint paths in the harness.
- Bind the PyTorch profiler to the first configured updates of the same measured
  window, derive trace metrics from the published Chrome trace, and record both
  measured-window and successful-update ranges.
- Time DiT, loss, backward, clip, optimizer, and zero-grad at their real boundaries;
  preserve caller-recorded Qwen/VAE/conditioning phases; count kernel and governed GPU
  memcpy/memset intervals as active, unknown GPU work as unattributed, and retain
  kernel-specific gap/launch/NCCL and fusible-group shares.
- Reject workload drift, feature removal, undisclosed memory growth, any host swap,
  tail regression, combined compile/backend retention claims, any measured-window
  compile/recompile/fallback, missing checkpoint cadence, CPU-only traces presented as
  GPU evidence and out-of-range traces. Nsight collector smokes cannot enter a formal
  trace index; formal Nsys/NCU indexing stays blocked until a marker/range/kernel
  importer verifies the report itself.
- Atomically/no-clobber publish raw samples, summary, hotspot decisions, comparison,
  compile evidence, and trace indexes; re-hash traces by streaming at publication.
- Keep `compile.regional_enabled=false` in the current strict schema. Future enablement
  requires an isolated compile-only comparison with identical attention backend and
  zero swap, plus hash-bound correctness, 4GPU DDP, 4GPU resume, zero-recompile, and
  zero-fallback evidence in addition to the configured end-to-end gain gate.
