# A001: 本地资产审计方案撤销

状态：已撤销并简化；不再阻塞单卡主线

## 变更决定

用户已确认 Qwen TE 与 Mage-VAE 分别准备在 `model/qwen_3.5_2B/` 和 `model/vae/`。本项目是个人兴趣项目，不再为这些已准备的本地资产维护逐文件 bytes/SHA-256、manifest 自哈希、repo/revision/license、DB schema hash、reference Git 身份或 capability 签发体系。

原 A001 的以下范围全部撤销：

- `assets/manifest.toml` 及其 schema、hash report、license/source report。
- 对本地模型、DB 和参考工程做逐文件 bytes/SHA-256 审计。
- asset inspection CLI、verified identity/capability、发行登记、TOCTOU/hostile-local-environment 防护。
- 为上述机制维护的专属实现、测试和多轮审查证据。

## 保留的最小边界

- Qwen 只从固定本地目录 `model/qwen_3.5_2B/` 加载。
- Mage-VAE 只从固定本地目录 `model/vae/` 加载。
- 实际加载前检查目录和加载所必需的文件是否存在；缺失时明确失败。
- 禁止自动下载、缺失补下载、联网替换和任何 fallback。
- 模型、DB、dataset/cache、`reference/` 与训练 artifact 继续保持 Git 忽略。
- `reference/` 只供人工理解和对照，生产代码、测试、preflight、训练和运行时不得 import、执行或调用其中代码。

Qwen/Mage-VAE 的真实配置、接口、forward 和质量验证分别归 `T021`/`T020`；DB/metadata 只在数据任务实际需要时按 schema 读取。D010 对远端 WebDataset shard 的 bytes/SHA-256 校验属于网络传输完整性，不受本次撤销影响。

## 结果

A001 不再要求独立资产 manifest、哈希扫描、CLI、capability 或审查轮次，也不再作为 `D010`、`T020`、`T021` 的前置阻塞项。
