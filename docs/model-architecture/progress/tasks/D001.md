## 动作与验收

- 为现行条款分配稳定 ID，显式标记 superseded 历史项，建立 requirement→config→module→test→benchmark→artifact 映射。
- checker 双向验证现行 requirement 与关键模块/配置键；故意删除映射的负测试必须失败。
- 校验 archive SHA-256 不变，current 文档演进有 changelog。
- 实现摘要、针对性测试、耗时与 artifact 证据随 D001 单独提交；AI/Infra 在 Foundation 包末审查。

## 实现结果

- 三份 canonical current source 当前共登记 221 个规范节点；每条 requirement 直接保存 config、module、reference、test、benchmark、artifact 映射，不只依赖 profile 隐式继承。
- checker 固定 source/scope，验证稳定 locator、状态图、硬件门槛、真实 review/artifact、双向生产库存、archive checksum/symlink、current SHA changelog 和非 archive 文档链接。
- archive 校验先对 `SHA256SUMS` 使用独立 bootstrap SHA-256 信任锚，再验证逐文件 hash；同时篡改 archive 与 checksum manifest 不能通过。
- requirement ID 使用可信 bootstrap binding 摘要与逐 revision Git 历史绑定；即使没有 Git 历史，交换 bootstrap ID 也会硬失败。旧 ID 不得删除，历史 locator 不得转移给其他 ID，新 ID 必须使用对应前缀从未使用且高于历史最大值的 serial。
- 反向生产模块库存忽略仓库根级 `src/sakuramoon/**` 横切边界映射，只接受具体 requirement/profile 模块映射；新增无领域所有权模块会硬失败。
- 36 个正负 contract 测试、完整 CPU 回归、Ruff、严格 Pyright、lock 检查和独立 checker 均通过。GPU 未使用。
- Foundation 独立 AI/Infra 审查发现 bootstrap identity 与 blanket module glob 两项缺口；修复后的逐项主代理验收见 `docs/model-architecture/reviews/D001/ai_review.md` 与 `infra_review.md`。因直接启动复审代理未返回有效任务名，未伪造独立复审结论。
