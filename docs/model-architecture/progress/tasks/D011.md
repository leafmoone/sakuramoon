## Scope

- Parse the canonical `id`, `release`, `width`, `height`, and `caption_available` contract while preserving the original mapping for D014.
- Bind raw metadata through caller-supplied field names with no code defaults. Take `release` only from the selected immutable D010 shard record, never from untrusted sample metadata.
- Report duplicate logical IDs in an in-memory scan.
- Select exactly 2,000 unique validation IDs deterministically across `release x aspect bucket x caption availability` strata.
- Exclude the selected IDs before downstream shuffle or sample processing.
- Publish canonical `validation_manifest.jsonl` and one independent deterministic WebDataset tar as a no-clobber, fsynced, atomically renamed directory.

The aspect-bucket resolver is injected by the caller because the 17-bucket image routing belongs to D013. The production raw field names and exact caption-availability source remain explicit runtime inputs because current decisions do not define them. D011 does not create a database, index service, or distributed coordinator.

## Implementation

Selection uses a caller-provided seed and SHA-256 ranking. Every non-empty stratum receives one slot, then remaining slots are assigned proportionally to remaining stratum capacity with deterministic largest-remainder ties.

The bundle writer requires exactly the sorted 2,000 selected IDs and streams one sample
at a time into a deterministic USTAR archive. Member suffixes are path-safe, sorted,
and unique; tar uid/gid/names/mtime/mode are fixed. The manifest and tar are file-fsynced
inside a temporary sibling directory, the directory is fsynced, then the whole bundle
is renamed and the parent directory fsynced. Existing destinations fail before payload
publication.

## Evidence boundary

Synthetic tests prove the contract, explicit alias mapping, trusted shard release, exact cardinality, uniqueness, determinism, input-order independence, stratum coverage, duplicate rejection, JSONL/tar stability, strict shard ID equality, no-clobber publication, cleanup after drift, and zero selected IDs after exclusion. They do not prove the production metadata field-name choice, global uniqueness across approximately 11M samples, final stratum distribution, a real-payload validation bundle, or a complete training dry-run zero-leak result.

Validation: 31 targeted tests passed in 2.13 seconds; the full CPU suite passed 489 tests in 36.01 seconds with 24 warnings. Ruff and strict Pyright passed. Traceability and lock checks are recorded in the task report.

Data package review found that a whitespace or non-string aspect bucket key could enter
the selection strata. The resolver boundary requires a non-empty, trim-stable string
and rejects invalid values with `ValidationSelectionError`. The production metadata
field names, approximately 11M-ID uniqueness scan, real-payload validation bundle, and
full training zero-leak dry run remain pending. Fresh independent review of the new
mapping and publication paths is also pending.
