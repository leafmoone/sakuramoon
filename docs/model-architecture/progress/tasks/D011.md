## Scope

- Parse only the currently defined `id`, `release`, `width`, `height`, and `caption_available` fields. Preserve the original mapping for D014 without claiming a complete production metadata schema.
- Report duplicate logical IDs in an in-memory scan.
- Select exactly 2,000 unique validation IDs deterministically across `release x aspect bucket x caption availability` strata.
- Exclude the selected IDs before downstream shuffle or sample processing.

The aspect-bucket resolver is injected by the caller because the 17-bucket image routing belongs to D013. D011 does not inspect `db/`, dataset payloads, model weights, `.env`, or `reference/`, and does not create a database, index service, validation shard, or distributed coordinator.

Selection uses a caller-provided seed and SHA-256 ranking. Every non-empty stratum receives one slot, then remaining slots are assigned proportionally to remaining stratum capacity with deterministic largest-remainder ties.

## Evidence boundary

Synthetic tests prove the contract, exact cardinality, uniqueness, determinism, input-order independence, stratum coverage, duplicate rejection, JSONL stability, and zero selected IDs after exclusion. They do not prove the production metadata field mapping, global uniqueness across approximately 11M samples, final stratum distribution, independent validation shard publication, or a complete training dry-run zero-leak result.

Validation: 19 targeted tests passed in 0.34 seconds; the full CPU suite passed 351 tests in 30.48 seconds. Ruff, strict Pyright, lock check, and traceability verification passed.

Data package review found that a whitespace or non-string aspect bucket key could enter
the selection strata. The resolver boundary now requires a non-empty, trim-stable
string and rejects invalid values with `ValidationSelectionError`. The production
metadata mapping, approximately 11M-ID uniqueness scan, exact validation shard, and
full training zero-leak dry run remain pending.
